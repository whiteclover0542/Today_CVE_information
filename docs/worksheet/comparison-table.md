## 손계산 — 증감 계산

- 계산식: 최신 − 이전 = 13 − 212 = **−199**
- 방향: 음수 → 감소
- 단위: 건
- `app.js`의 `renderCompare()` 로직을 손으로 그대로 따라가면 비교 카드 문구는 다음과 같이 나와야 함:
  `-199건 (2026-08-23 212건 → 2026-08-24 13건, 감소)`
- 배포 화면(`https://whiteclover0542.github.io/Today_CVE_information/`)에서 2026-08-24 확인한 실제 값 카드: **13건**, 비교 카드: 위 문구와 동일 — 손계산과 일치

## 측정 구간 차이 — 위 −199를 그대로 "감소했다"로만 읽으면 안 되는 이유

두 기록의 조회 시각이 09:00 KST 예정과 다르게 각각 **19:18**(전날 저녁 기능 추가 작업 중 재조회) / **09:30**(당일 정상 스케줄)로, 누적 구간 길이가 다름(19시간18분 vs 9시간30분). 즉 −199 중 상당 부분은 "실제 발생량이 줄어든 것"이 아니라 "이전 기록이 더 늦은 시각까지 누적된 값이라 더 큰 것"에서 온다. 값 자체를 보정하지 않고(위조 금지), 비교 카드 옆에 두 조회 시각을 그대로 노출해 이 사실을 화면에서 확인할 수 있게 함(`assets/app.js`의 `renderCompare()` 내 `compareWindowNote`).

## 재검증 절차 (평가자용, 3단계)

1. `data/history.json`의 두 `sourceApiUrl`을 각각 열어 `totalResults`가 같은 파일의 `count`와 같은지 확인
2. `count` 두 값을 손으로 빼서(13−212=−199) 화면 비교 카드 문구와 같은지 확인
3. 공개 주소를 열어 값 카드(13건)·비교 카드(−199건, 감소)·조회 시각 목록이 위 표와 같은 숫자로 보이는지 눈으로 확인
